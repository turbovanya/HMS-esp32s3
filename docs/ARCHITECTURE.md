# Как устроена прошивка

## Поток данных

```
датчики -> SensorValue (сглаживание EMA, признак свежести)
        -> History (отсчёт раз в 10 с, давление раз в 5 мин)
        -> UiData (значения, состояния, тренды)
        -> uiUpdate (анимации, нужно ли перерисовывать)
        -> uiDraw (рисование в кадровый буфер)
        -> дисплей
```

Главный цикл в `MeteoStation.ino` неблокирующий: датчики опрашиваются по своим таймерам,
MH-Z19B читается конечным автоматом (запрос, ожидание ответа, тайм-аут), PMS7003 разбирается по байтам.
Раз в 80 мс собирается `UiData`, и если картинка изменилась, рисуется кадр.

## Состояния датчиков

У каждого показателя три состояния (`SensorState` в `Ui.h`):

- `S_OK`: данные свежие, не старше 8 секунд;
- `S_WARMUP`: данных ещё не было, и не вышло время прогрева (CO2 3 мин, VOC 2 мин, пыль 45 с, климат 15 с);
- `S_LOST`: данные были и пропали, или не появились за время прогрева.

## Рендер (`Gfx.cpp`)

Свой мини-рендер поверх буфера RGB565, без внешних графических библиотек.
Adafruit ST7789 используется только для инициализации дисплея и отправки готового кадра.

- **Кадровый буфер** 320x240x2 = 150 КБ во внутренней памяти. Если столько не найдётся, кадр
  рисуется полосами: сцена прогоняется отдельно для каждой полосы (240, 120, 80... строк).
- **Сглаживание** считается через знаковые расстояния: скруглённые прямоугольники, круги, дуги
  с круглыми концами, линии и выпуклые многоугольники получают дробное покрытие на краях.
- **Шрифты** 4-битные (16 уровней прозрачности), с кириллицей, ищутся по коду символа
  двоичным поиском, текст в UTF-8.
- **Дизеринг**: фон и карточки залиты тёмными градиентами, в RGB565 они дали бы полосы.
  Упорядоченный дизеринг Байера 4x4 убирает полосы. Шаблон повторяется каждые 4 пикселя,
  поэтому строка заливается готовым шаблоном, а не считается попиксельно.
- **Дуги индекса** рисуются через `PolarCache`: для неподвижного центра кольца угол и расстояние
  каждого пикселя считаются один раз при старте. Корень на этом чипе стоит ~365 нс, atan2 больше
  микросекунды, а с таблицей дуга обходится без них.
- **Углы карточек** берутся из заранее посчитанной маски для каждого радиуса.
- Графический код собирается с `-O2` (`#pragma` в начале `Gfx.cpp`), остальное с `-Os`.

## Интерфейс (`Ui.cpp`)

- Раскладка задаётся таблицей `Box` (координаты и радиус каждой карточки). По этой же таблице
  фон пропускает области, которые карточки всё равно закроют.
- Индекс воздуха: каждый показатель переводится в балл 0..100 по кусочно-линейной таблице,
  итог равен худшему баллу.
- Анимация: отображаемое значение каждый кадр приближается к реальному (`Anim::step`),
  индекс при старте «набегает» с нуля.
- `uiUpdate` считает хеш того, что видно на экране (округлённые значения, состояния, тренды).
  Кадр рисуется, только если хеш изменился, идёт анимация или пульсирует кольцо. В покое
  экран обновляется раз в 5 секунд.

## Производительность

Замер на плате (команда `i`):

| Этап | Время |
|---|---|
| Рисование кадра | ~29 мс |
| Передача в дисплей (SPI 40 МГц) | ~39 мс |
| Итого | ~68 мс, около 15 кадров/с во время анимации |

Свободно после старта около 150 КБ памяти: буфер кадра 150 КБ и таблица кольца 54 КБ уже выделены.

## Снимок экрана по USB

По команде `s` прошивка шлёт строку `SHOT 320 240`, затем 153 600 байт кадра (RGB565, младший
байт первым), затем `END`. `tools/screenshot.ps1` превращает это в PNG. Кадр снимается из того же
буфера, что уходит в дисплей, поэтому снимок точно совпадает с экраном.
